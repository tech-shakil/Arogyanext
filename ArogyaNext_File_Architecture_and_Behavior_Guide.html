1. High-Level System Architecture & Cross-Panel Data Flow

ArogyaNext is built as a multi-tenant cloud hospital operating system using React 19, Vite 8, Tailwind CSS 4, and Firebase Firestore / Auth. Every clinical workflow connects without manual paper handoffs.

+--------------------------------------------------------------------------------------------------+ | AROGYANEXT CLINICAL PIPELINE | +--------------------------------------------------------------------------------------------------+ [Patient Voice / Receptionist] | v appointments collection (status: "Waiting", tokenNumber: "S-14" / "E-99", hospitalId, doctorName) | +-----------------------+----------------------------------+ | | | v v v [Doctor Workspace] [Smart Prescription Pad] [TV Waiting Room Display] - View waiting queue - Blank letterhead overlay - Soundwave TTS Audio Callout - Review OCR paper Rx - Stylus digital signature - Real-time Neon queue board - Digital prescription - Auto-print to hardware printer - Continuous Marquee ticker | | +-----------+-----------+ | v (status: "Completed", pharmacyStatus: "Pending", prescription: "Dolo 650mg...") | v [E-Pharmacy Hub] ------------------------> [Hospital Admin Analytics] - Instant medicine alert - CSV Audit Reports (Day/Week/Month/Year) - 1-click Dispensed action - Footfall & Wait-time metrics

2. Firebase Firestore Database Collections & Schema Design

Collection Document ID Key Key Fields & Types Panel Usage & Purpose
users auth.uid uid, email, fullName, role, hospitalId, createdAt Auth & profile management. Controls tab visibility and multi-tenant scoping.

appointments Auto-generated UUID tokenNumber, patientName, patientAge, symptoms, doctorName, hospitalId, status, isEmergency, appointmentDate, timeSlot, timestamp, prescription, pharmacyStatus, scannedPrescriptionText Heart of the application. Tracks the end-to-end lifecycle of patient consultations and medicine fulfillment.
doctor_status doctorName status ('Active'|'Away'|'In Consultation'), currentToken, lastUpdated Global availability indicator for doctors, allowing reception and patients to see doctor availability.
queue hospitalId activeDoctor, activeToken, status, lastUpdated Broadcast queue state synced across TV lobby monitors and companion devices.
ℹ️
Multi-Tenancy Security Rule: Every single query across reception, doctor cabins, pharmacy, and analytics strictly filters by hospitalId == userProfile.hospitalId. Data never leaks across clinics or hospital branches.

package.json Config & Manifest
Path:/package.json
Type:Node.js ES Module Manifest
Scripts:dev, build, lint, preview
Frameworks:React 19.2, Vite 8.0, Tailwind CSS 4.2
What It Contains:

Declares project dependencies, build toolchains, and runtime dependencies. Key packages include: firebase (v12.11) for Firestore and Authentication, lucide-react (v0.577) for clinical icons, @tailwindcss/vite and tailwindcss (v4.2) for utility CSS, and eslint (v9.39) for React hooks linting.

  • Zero bloated dependencies: No heavy external UI component kits; built with native DOM APIs, Canvas, SpeechSynthesis, and Tailwind for performance.

src/App.jsx Root Orchestrator & View Switcher
Path:/src/App.jsx
State Hooks:user, userProfile, currentView, isAuthenticating, showAuthScreen, mobileMenuOpen
Listeners:onAuthStateChanged(auth)
Tabs Handled:receptionist, doctor, smartPad, pharmacy, hospitalAdmin, tv, admin
What It Contains:

Acts as the brain of the frontend application. It orchestrates user authentication, role-based access control (RBAC), multi-device responsive navigation, and conditional rendering of the appropriate clinical panel.

Detailed Runtime Behavior & Flow:
  • Auth Initialization: While verifying auth tokens, renders a dark animated splash screen with a bouncing caduceus (⚕️).
  • Public vs Staff Gate: If no user is logged in, renders <LandingPage />. If the user clicks "Staff Login", toggles showAuthScreen = true to display <Auth /> with a back button.
  • Role Routing on Login: Upon login, queries users/{uid} from Firestore. Dynamically defaults the active view based on profile.role: Doctor → Doctor Workspace, Pharmacist → E-Pharmacy, Hospital Admin → Analytics Hub, Super Admin → Founder Console, Receptionist → Front Desk.
  • Role-Based Navigation Tabs: Filters the master tab array so staff can only see and access authorized modules. For example, doctors see Doctor & Smart Pad; pharmacists see Pharmacy & TV; Super Admins see all 7 modules.
  • Mobile UI Support: Features dual mobile navigation: an interactive hamburger drawer and a horizontal scrollable pill bar, ensuring effortless one-thumb operation on smartphones.
  • Header Bar: Displays the hospital access code (e.g. HOSP_X92K), authenticated staff name, role badge, and a one-click signOut() action.
src/Auth.jsx Staff Authentication Portal
Path:/src/Auth.jsx
State Hooks:isLogin, isForgotPassword, email, password, fullName, hospitalId, role, showPassword, isLoading, error
Firebase APIs:signInWithEmailAndPassword, createUserWithEmailAndPassword, sendPasswordResetEmail, setDoc
What It Contains & Detailed Behavior:
  • Tri-Mode Form: Smoothly switches between Sign In, Create Staff Account, and Forgot Password.
  • Hospital ID Validation: When creating a staff account (unless role is Super Admin), checks if hospitals/{hospitalId.toUpperCase()} exists in Firestore. If invalid, blocks signup and alerts the user.
  • Automatic Doctor Directory Registration: When a user with the role "Doctor" registers, the component creates both a users/{uid} document AND a doctors/{uid} record so front-desk staff can assign patients to them immediately.
  • Security & UX: Features an eye icon to toggle password visibility, uppercase auto-formatting for hospital codes, and self-clearing error banners with friendly messages.

src/ReceptionistPanel.jsx Front Desk Control Center
Path:/src/ReceptionistPanel.jsx
Props:hospitalId
State Hooks:patientName, patientAge, symptoms, selectedDoctor, isEmergency, appointmentDate, timeSlot, doctorsList, todaysPatients
Firestore Listeners:onSnapshot(appointments where status == 'Waiting' & date == today)
Detailed Behavior & Logic:
  • Doctor Sync: On mount, queries doctors filtered by hospitalId to populate the doctor dropdown with real names and specialties.
  • Smart Token Generation: Normal appointments generate S-XX tokens (e.g. S-42). Emergency walk-ins generate E-XX tokens (e.g. E-12) and bypass time slot requirements with status set to IMMEDIATE.
  • Live Grouped Queues: Groups today's waiting appointments by doctor cabin in real-time. Receptionists can monitor workload distribution across all cabins simultaneously.
  • Appointment Cancellation: Receptionists can cancel an appointment with a single tap, updating the Firestore status to Cancelled and removing the patient from doctor queues.
  • OCR Indicator: If a patient booked via mobile with an uploaded prescription, an 📷 OCR Rx badge appears alongside their token.
src/DoctorPanel.jsx Doctor Clinical Workspace
Path:/src/DoctorPanel.jsx
Props:hospitalId, doctorName
State Hooks:waitingPatients, currentPatient, prescriptionText, currentStatus ('Active'|'Away')
Updates:appointments, doctor_status
Detailed Behavior & Logic:
  • Doctor-Scoped Waiting Queue: Real-time snapshot listener listening only for patients assigned to this doctor with status Waiting. Emergency patients flash red at the top.
  • Call In Action: When the doctor clicks "Call In", the appointment status changes to In Consultation and the doctor's document in doctor_status updates with currentToken, triggering notifications across the TV display and companion apps.
  • Scanned Paper Rx (ML Kit OCR) Review: Displays the patient's scanned previous prescription text in a monospaced preview card. The doctor can click "+ Insert into E-Prescription" to append those notes into the digital prescription.
  • Finish Consultation & E-Pharmacy Sync: Doctor enters medicine notes and clicks "Finish Consultation". This sets appointment status to Completed and, if medicines were typed, sets pharmacyStatus = 'Pending', routing the prescription to the hospital pharmacy counter.

Section 6: Specialized Digital Health Panels
src/SmartPrescriptionPanel.jsx Smart Letterhead & Stylus Signature
Path:/src/SmartPrescriptionPanel.jsx
Props:hospitalId, doctorName
Key Tech:HTML5 Canvas (2D Context), LocalStorage Base64, CSS Print Media
Controls:Margin Top slider, Signature Bottom slider, Mask Lines toggle
Detailed Behavior & Logic:
  • Custom Letterhead Upload: Doctors can upload a PNG/JPEG image of their clinic letterhead. The file is converted into Base64 and stored in localStorage per doctor, loading instantly on subsequent visits.
  • Pixel-Perfect Calibrated Alignment: Doctors use sliders to align where patient info and prescription text appear over their printed letterhead lines, and can toggle "Mask Background Lines" to prevent text collision.
  • Stylus Signature Pad: Uses a 2x retina-scaled HTML5 Canvas with pointer event listeners (onPointerDown, onPointerMove, onPointerUp) supporting Apple Pencil, Surface Pen, or touch signatures.
  • Print & Pharmacy Sync: When clicking "Finish, Send & Print", the component updates Firestore (routing to pharmacy) and invokes window.print(). Using print CSS, the UI toolbars disappear and only the letterhead prescription prints.
src/TVDisplay.jsx Lobby TV Signage & Voice Announcements
Path:/src/TVDisplay.jsx
Props:hospitalId
APIs Used:Web Speech API (speechSynthesis), Firestore Real-Time Query
Visuals:Blinking Digital Clock, Neon Active Token Glow, Audio Equalizer Bars, Marquee Notice
Detailed Behavior & Logic:
  • Full Screen TV Layout: Designed for 55"+ smart TVs mounted in hospital waiting lobbies. Displays high-contrast text readable from across the room.
  • Multi-Doctor Cabin Grid: Dynamically splits into side-by-side cards for each doctor on duty. Left half shows the active token in glowing emerald font; right half shows the next 4 patients in line.
  • Speech Synthesis (TTS) Engine: When any doctor calls a token, an utterance is synthesized: "Token number S 14, please proceed to Dr. Sharma's cabin." Accompanied by a floating announcement banner and animated equalizer bars.
  • Continuous Broadcast Marquee: Bottom ticker displays clinic notices, reminding patients about token announcements and emergency procedures.
src/PharmacyPanel.jsx E-Pharmacy Fulfillment Counter
Path:/src/PharmacyPanel.jsx
Props:hospitalId
Firestore Listener:appointments where hospitalId == id & pharmacyStatus == 'Pending'
Detailed Behavior & Logic:
  • Real-Time Medicine Queue: Real-time listener for any appointment in the facility where pharmacyStatus == 'Pending'. When a doctor finishes a consultation, the order appears immediately.
  • Prescription Cards: Displays patient name, prescribing doctor, emergency badge (if urgent), and full medicine list.
  • Fulfillment Action: Pharmacist prepares medicines and clicks "Mark as Dispensed ✅", updating the record to pharmacyStatus = 'Dispensed' and clearing the card from the active queue.
